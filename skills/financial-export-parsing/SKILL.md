# 金融导出文件解析

## When to Use

用户放入真实账单/余额文件（微信支付账单、支付宝交易明细、银行流水 PDF、Excel 余额快照）需要读取分析时。

## 核心原则

1. 工具适配人的习惯：用户给什么格式就解析什么格式（CSV/Excel/PDF 混合存放，按扩展名自动分发）。
2. 所有金额计算用代码，禁止语言模型心算。
3. 解析结果中的关键数字要能追溯到来源文件。

## 真实导出文件的五大陷阱

### 1. 表头不在首行（元信息行）

微信支付账单 xlsx 前 17 行是元信息，表头在第 18 行。

- 解法：对前 N 行做**关键词评分**（包含"日期"/"金额"/"交易对方"/"收 支"/"摘要"等关键词的个数），得分最高的行为表头。

### 2. 非 UTF-8 编码

支付宝交易明细 CSV 是 GBK 编码。

- 解法：编码探测链 **utf-8-sig → gb18030 → latin-1**，逐个尝试。

### 3. PDF 无表格线

招商银行流水 PDF 是文本排版、无表格线，extract_tables() 返回空。

- 解法：fallback 到 **extract_text() 按行解析**，按固定列宽分桶。

### 4. 横表 vs 竖表

余额快照常见横表：第一行"日期 | 账户A | 账户B | …"，后续行"日期 | 余额A | …"。

- 解法：表头首列是"日期"且后续列可解析为金额 → 检测为横表，按列转竖表。

### 5. 列内垃圾值

微信"商品"列在商品名未知时填"商户单号xxx"（超长无意义串）。

- 解法：值为 "/"、"-"、以"商户单号"开头、或匹配超长正则时，回退用"交易对方"。

## 标准化与别名映射

- 列名别名全覆盖（中英文与平台差异）。
- 日期规范化：多种格式 → YYYY-MM-DD。
- 金额清洗：千分位、¥/$ 符号、负数括号。

## 验证方法（必做）

1. **混合格式端到端**：造 CSV+Excel+PDF 三格式测试数据，断言关键数字。
2. **幂等测试**：同一批数据跑两次，第二次应 0 新增。
3. 边界用例：冻结/受限资金排除、退款配对抵消、跨平台疑似重复。

## 常见坑

- Windows 上 patch 含反斜杠路径的文本时，`\r` 会被当转义符吃掉；路径一律写正斜杠。
- 累积账本用交易指纹去重保证幂等。
- 生成测试 PDF 必须注册中文字体：reportlab 用 `UnicodeCIDFont("STSong-Light")` 并设 FONTNAME。
